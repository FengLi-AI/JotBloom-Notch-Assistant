# 萌生 JotBloom V1.0.7 PRD 产品需求文档

版本：Mac 1.0.7｜基线：1.0.6｜日期：2026-09-23｜状态：已实现，按用户确认发布 1.0.7

## 1. 背景与目标

在整理资料、上传附件或跨应用发送文件时，用户需要反复找到原文件，再切换到目标应用。我的目标是让萌生提供一个随手可用的中转入口：**先拖进刘海，需要时再拖出去，使用的始终是原文件。**

本版聚焦文件流转效率。只保存原文件引用，避免重复占用空间和产生多个版本；不引入 AI 识别、整理或读取文件，因为这不是完成中转所必需的能力。

## 2. 用户场景与流程

面向经常跨应用处理文件的 Mac 用户。典型场景：从下载目录找到方案，先放进中转站，稍后分别拖到聊天附件区和网页上传区，无需再次翻找目录。

两种加入方式：

- **快速暂存：**文件拖入刘海区域 → 提示“松手即可放入中转站” → 松手并保存引用成功 → 显示“已收录至中转站”，彩色描边闪动后触发小伙伴收录反馈。全程不弹出面板，新文件放到第一位。
- **指定位置：**用户自行打开中转站 → 从外部拖入文件，或拖动已有文件 → 选择位置松手 → 吸附到网格，面板保留。

需要使用时，从中转站将文件拖到目标应用，在目标应用完成上传或发送。

## 3. 版本范围

| 本版做 | 本版不做 |
| --- | --- |
| 本地文件／文件夹引用、批量拖入与拖出、跨重启保留 | 文件副本、云存储、跨设备同步、分享链接 |
| 网格拖动排序、类型／时间筛选、批量选择与移除 | 文件正文读取、AI 处理、文件名搜索、自动下载云端文件 |
| 打开、定位、撤销、清空、失效处理及配套导航调整 | 固定置顶、自动过期、Windows 新功能 |

全部属于 Mac 免费开源功能，无需登录或激活。

## 4. 核心需求

| 功能 | 产品规则 |
| --- | --- |
| 加入文件 | 刘海区域和中转站网格接收已下载到本机的文件／文件夹；无刘海屏通过页面加入。刘海悬停只显示收录提示，松手且引用保存成功才算加入；取消不新增。 |
| 批量与去重 | 逐项反馈新增、重复、失败数量。同一原文件只保留一条；刘海松手时放到网格最前，指定位置松手时插入该处。多个文件连续落位，不打乱其他条目的相对顺序；不同目录的同名文件分别保留。 |
| 保存方式 | 仅保存路径、文件身份及必要展示信息；不复制、移动、改写原文件，不创建实体快捷方式。引用和手动顺序跨重启保留，拖出后不自动移除。 |
| 拖出文件 | 向目标应用交接原文件附件，不能只传路径文字；原文件更新后使用最新内容。萌生不代替用户发送，也不把拖出反馈成“上传成功”。 |
| 选择与操作 | 单击选中；⌘ 单击增减选择、Shift 单击连续选择，并提供批量选择入口和已选数量。全选仅选当前筛选结果；切换类型或时间清除选择，避免误操作隐藏项。双击／Enter 打开，支持在 Finder 中定位。 |
| 批量移除与清空 | 支持移除单项或全部选中项，文案为“从中转站移除”，只删引用并支持撤销。一键清空针对整个中转站，筛选状态下也需明确总数量；确认文案“清空中转站的 N 项？不会删除原文件”，取消不变更。卸载也不得主动删除原文件。 |
| 现有功能兼容 | 文件拖入不重复保存成文字灵感；纯文字仍按原规则收录。复制文件不自动加入中转站。文件拖入独立开关默认开启，不依赖桌宠和文字收录开关。 |

“只保存引用”的承诺适用于萌生；目标应用接收附件后可能自行复制或上传文件。

## 5. 界面与交互

**顶部导航：**中转站使用文件夹图标，作为一级标签；搜索改为纯图标按钮，固定在设置左侧。保留物理刘海占位和现有按钮区域，六个业务标签均显示图标与中文名称；通过紧凑间距和文字自适应容纳，不把灵感库、中转站退化为纯图标。保留悬停说明、辅助功能名称和焦点状态。

**文件网格：**类似手机桌面图标，以文件图标／缩略图和文件名为主，目录及状态作为辅助信息。长名称保留扩展名，同名文件可区分目录。默认／展开状态自适应列数与可见行数，双向连续过渡，不先闪到目标布局；分类栏、文件位置和图标尺寸同步变化，保持原顺序；保存顺序而非固定像素坐标，避免缩放后位置错乱。空状态提示“拖入文件，稍后从这里拖出使用”。

**拖动落位：**拖起时移除原位置占位，网格只保留一个目标占位；多选拖动也用一个占位代表整组。占位为比卡片小一圈的浅色虚线框，相邻文件平滑让位，松手后自动吸附，不闪动、不重叠。已有条目可直接拖动改变位置；多选后按原相对顺序成组移动，拖未选中项则只操作该项。靠近上下边缘可滚动到其他位置。网格内松手提交排序；拖出网格后立即恢复完整排列，不留占位和空洞，成功交给外部应用后收起面板。取消或外部拒收保留原顺序，不因拖出而误改位置。

**类型优先：**主要分类为“全部／图片／文档／视频／音频／压缩包／文件夹／其他”，默认“全部”。文档包含 PDF、文本、表格和演示文稿；无法识别的类型归入“其他”，文件夹不按内部内容分类。默认窗口使用紧凑类型标签，放不下时可横向滚动；展开后用分类侧栏，时间入口保持次级位置。

**时间辅助：**提供“全部时间／今天／昨天／按月份与具体日期”，默认“全部时间”，按首次加入中转站的本机日期筛选。移动位置、重复加入不改变日期。类型与时间可组合，例如“图片 + 今天”；两个条件同时满足才显示。切换类型保留时间条件，当前条件清晰可见，可一键重置；无结果时提示调整或清除筛选。

**筛选与整理：**筛选不改变手动顺序；筛选内排序只调整可见项在整体顺序中占据的位置，未显示项顺序不变。向已打开的网格拖入时临时切到“全部类型 + 全部时间”，让落点和新增项可见；取消恢复原筛选。刘海快速收录不切换当前页面和筛选。

**刘海收录反馈：**文件悬停与灵感收录使用同一套提示、吸收、彩色描边和小伙伴反馈；不自动展开或切换页面。保存成功才显示成功反馈；失败或部分失败提示未收录并可打开中转站查看详情，不能虚报全部成功。桌宠关闭时仍可正常收录及显示提示，文字收录开关不影响文件收录。

**操作保护：**文件收录不得丢失原页面的未保存内容，也不改变默认入口。拖出期间不因失焦而中断；取消后保留面板和选中状态，目标接收后可收起，但不抢走目标应用焦点。原有全屏及刘海热区禁用规则继续生效。

**导航兼容：**默认顺序为“灵感、灵感库、剪贴板、提示词、中转站、对话”；⌘1～⌘6 对应实际顺序，默认 ⌘5 为中转站。搜索与设置固定在最右侧，不参与排序，快捷键仍为 ⌘F、⌘,。旧默认顺序更新，旧自定义顺序保留（其中搜索位置由中转站替换）；搜索保留旧默认入口，中转站可设为默认入口。发布说明需提示快捷键变化。

**内容卡片反馈：**剪贴板、提示词、灵感库默认使用普通边框，不自动突出第一项；按下卡片时显示轻微蓝色反馈，松开淡出。使用方向键时才显示轻微定位框，方便继续操作。

## 6. 异常与边界

| 场景 | 用户体验要求 |
| --- | --- |
| 原文件改名、移动或被替换 | 能确认原文件则更新引用；无法确认时标记不可用，允许重新选择，不能误发同名的其他文件。 |
| 文件删除、外接盘断开、无权限 | 说明原因，禁止无效拖出，保留记录供刷新、重新选择或移除；不引导申请全盘访问。 |
| 云端未下载、远程链接、未落盘附件 | 提示先保存到本机，不自动下载、生成副本或转成文字灵感。 |
| 多选中有失效项 | 阻止本次拖出并指出问题，不悄悄只发送部分文件。 |
| 取消、拒收、上传失败 | 原文件和引用都保留；萌生不主动移动或删除源文件。 |

文件夹不自动遍历或压缩，能否接收由目标应用决定。引用信息仅用于本地功能，不进入 AI 请求或记录到日志；迁移数据目录只迁移引用，不搬动原文件。

## 7. 验收与效果判断

开发进度与验证边界见 [V1.0.7 开发验证记录](萌生-JotBloom-V1.0.7-开发验证记录.md)。

验收清单（实际覆盖情况见开发验证记录）：

- **引用正确：**大文件加入后无副本；重启可继续使用；原文件更新后拖出最新内容；移除、清空、卸载不影响原文件。
- **真实可用：**在 Safari、Chrome 上传区及微信、飞书附件区，验证文件被接收且可打开。中文名、同名文件、文件夹和批量拖出分别检查；发送测试使用测试会话或草稿。
- **异常可恢复：**覆盖取消、失效、断盘重连和无权限，不误发、不误删、不虚报成功。
- **拖入与落位：**验证刘海悬停提示、松手收录到首位、成功描边及小伙伴反馈，全程不弹面板；手动打开后可指定位置。排序只有一个较小虚线占位、让位连续，拖出后无空洞，取消不改顺序。
- **整理与筛选：**单项／成组拖动正确吸附，缩放及重启保留顺序，边缘滚动可用；类型为主、时间为辅，默认全部，组合筛选结果正确，未知类型归入其他。筛选排序不打乱隐藏项，切换条件不残留隐藏选择，重置与空结果提示可用。
- **批量操作：**批量移除只影响选中引用；筛选下清空明确针对全部记录，确认与取消均正确，源文件不受影响。
- **交互无回退：**默认／展开网格无遮挡；快捷键、导航设置和原有灵感、剪贴板、提示词及未保存内容正常。

效果判断：让试用者完成“同一文件分别交给两个应用”，观察是否还需回 Finder 重找、能否理解移除不删原文件、异常后能否自行恢复。本轮按用户确认发布；尚未覆盖的应用与设备组合继续收集兼容性反馈，不视为已验证。
