# 萌生 JotBloom V1.0.7 迭代需求文档

日期：2026-09-22

基线：Mac 1.0.6

目标：Mac 1.0.7

状态：后续开发计划，尚未实现。

## 1. 版本调整

按用户本次决定，将原 1.0.6 规划中尚未实现的「文件中转站」及配套顶部导航调整整体移至 1.0.7。1.0.6 仅交付现有剪贴板、提示词、灵感库的自适应布局与展开收起动效，详见 [1.0.6 需求文档](萌生-JotBloom-V1.0.6-迭代需求文档.md)。

## 2. 目标与范围

文件拖进刘海后，只保存原文件引用；需要上传或发送时，从中转站拖出原路径的文件。萌生不保存文件副本，不代替接收应用发送或上传。

纳入：文件／文件夹引用、多文件拖入、引用持久化、失效处理、拖出、定位与移除；中转站一级标签、搜索图标按钮和导航偏好兼容。

不纳入：云存储、跨设备同步、分享链接、自动下载云占位文件、临时导出副本、文件全文索引、AI 读取文件、付费能力和 Windows 新功能。

文件夹、多选、跨重启保留、拖出后保留、独立文件拖入开关沿用下文默认建议，属于待实现方案。以下验收要求不能作为功能已完成的说明。

## 3. 文件中转站

### 3.1 产品定义

中转站是一份用户主动加入的「原文件引用列表」。这里的“暂存”指暂存入口，不是暂存文件副本，也不是只能保留到本次退出。

例如：将下载目录中的 `方案.pdf` 拖进刘海后，它仍在下载目录。萌生只记住它的位置和展示所需的少量信息。用户从中转站拖到聊天附件区或网页上传区，目标应用接收的是这个原文件。

**必须满足的边界：**

- 加入时不复制、移动、改名或改写原文件，不创建指向它的实体快捷方式文件。
- 不将文件正文、完整二进制或临时导出副本保存到萌生数据目录。
- 拖出传递原文件的文件引用，不是路径文本、萌生内部记录或快捷方式文件。
- 原文件内容更新后，下次拖出引用其当时的内容，不提供加入时的历史快照。
- 移除、清空或卸载萌生都不得主动删除原文件。
- 目标应用可能自行复制附件、上传内容或生成缓存，这属于接收方处理；萌生承诺的是自身不额外保存文件副本。

### 3.2 主流程

```text
从 Finder 选中一个或多个本地文件
  → 拖到刘海本体，显示“松手加入中转站”
  → 松手，校验并保存引用，反馈加入结果
  → 需要使用时打开萌生，进入“中转站”
  → 拖动文件条目到目标应用的附件区 / 上传区
  → 由目标应用处理附件、上传或发送
```

默认加入后只做轻量反馈，不强制打开面板或切换用户正在编辑的页面。面板已经打开时，成功反馈提供「查看中转站」操作；用户主动点击后再切换。不得因此丢失灵感输入或提示词的未保存内容。

### 3.3 拖入规则

| 项目 | 建议规则 |
| --- | --- |
| 入口 | 物理刘海本体、中转站页面内容区；非中转站页面正文不成为全局接收区 |
| 支持对象 | 已有可访问本地路径的普通文件；文件夹只保存文件夹引用，不遍历导入内部内容 |
| 多项拖入 | 一次可以加入多个，逐项校验；正常项成功加入，失败项说明原因 |
| 去重 | 同一原文件重复加入只保留一条，并更新到列表顶部；不同目录的同名文件保留为不同条目 |
| 排序 | 默认按最近加入时间倒序；本版不增加手动排序和置顶 |
| 文件大小 | 加入不读取完整正文，不按文件体积复制数据；目标应用的上传限制由目标应用决定 |
| 文件夹 | 可以保存和拖出引用；目标应用是否接收文件夹需实测，不自动压缩或展开成多个文件 |
| 不支持 | 只有远程链接、内存图片、文件承诺或尚未落盘附件的拖拽；提示“请先将文件保存到本地后再拖入” |
| 云端占位文件 | 本版只保证已下载到本机的文件；未下载项提示先在原位置完成下载，不由萌生隐式下载 |

文件数据类型优先于拖拽附带的文字类型。一次拖拽只走一种主路径：有真实文件引用时走中转站，不再把同一项附带的文件名或路径保存成灵感；纯文字仍按已有规则保存到灵感库。不支持的文件拖拽也不能退化成“把路径保存成灵感”。

拖拽进入前只显示可接收状态，**松手且引用成功保存后**才能显示“已加入”。离开热区或取消拖拽不新增记录。

### 3.4 页面与操作

页面采用紧凑列表，优先显示文件名和文件类型，使用与其他列表页一致的底栏。

每行包括：小尺寸系统文件类型图标、文件名、弱化的父目录或状态，以及选中/悬停时出现的操作。文件名保留扩展名，中间截断长名称；完整名称和路径可通过悬停或详情提示查看。同名文件必须能通过父目录区分。

| 操作 | 行为 |
| --- | --- |
| 单击 | 选中条目，不自动打开或复制 |
| 拖动行 | 发起原文件拖出；与单击区分，避免刚按下就触发打开 |
| ⌘ 单击 / Shift 单击 | 建议支持多选 / 连续选择，随后批量拖出；未被选中的行开始拖动时，仅拖该行 |
| 双击 / Enter | 使用系统默认应用打开；文件夹在 Finder 打开；只有主动操作才执行 |
| 在 Finder 中显示 | 定位原文件，方便用户确认位置 |
| 从中转站移除 | 只删除引用；支持撤销，原文件不变 |
| 清空中转站 | 经确认清空引用；文案明确“不会删除原文件” |
| 刷新状态 | 重新检查引用是否可访问，适用于外接磁盘恢复连接等情况 |

移除使用叉号及「从中转站移除」文案，避免让用户误以为是在删除磁盘文件。中转站内拖动的主含义是拖出文件，不复用灵感库的排序拖动。

### 3.5 拖出与面板行为

- 提供系统文件拖拽，禁止将文件路径作为普通文字冒充附件。
- 发起拖出前重新检查原文件是否可访问；多选中有失效项时，本次阻止并指出问题，不悄悄发送剩余项。
- 一次拖出后仍保留记录，允许再次用于其他目标；取消、拒收或上传失败也不移除记录。
- 萌生只反馈已开始拖拽或目标接收情况，不显示“上传成功”“发送成功”。上传完成和发送确认由目标应用负责。
- 拖拽期间暂停会打断当前操作的失焦收起和自动切换，保证鼠标移出窗口后拖拽仍持续；释放或取消后恢复正常规则。
- 若用户取消拖拽，保留面板和选中状态；若目标接受且指针已在面板外，可收起面板，但不能把焦点强制抢回拖出前的应用，妨碍目标应用的附件确认。
- 萌生不主动移动或删除源文件，拖出以复制用途交接。对 Finder 等可能请求移动的目标，不协商会移走原文件的操作。

### 3.6 保存与失效规则

建议记录跨应用重启和系统重启保留，不自动过期、不因拖出自动清理。本版不增加可配置保留周期。

允许保存：记录 ID、原文件 URL/路径、必要的文件身份信息或轻量定位书签、文件名、类型、父目录、加入时间和最近检查状态。状态需在使用前刷新，不能把上次“可用”当成本次可用的保证。引用信息本身也是本地用户数据，不进入日志、版本库或 AI 请求。

| 原文件状态 | 用户看到什么 | 处理方式 |
| --- | --- | --- |
| 路径与访问正常 | 普通文件条目 | 可拖出、打开、定位 |
| 原文件修改 | 同一条目，必要时刷新名称等元信息 | 引用当前文件，不缓存旧内容 |
| 改名或移动 | 尽量通过文件身份/书签重新定位 | 成功则更新引用；失败则标记不可用，不承诺任意移动都能跟踪 |
| 删除或无法定位 | “找不到原文件” | 禁止拖出；保留条目供移除或重新选择文件 |
| 外接磁盘断开 | “原位置暂不可用” | 不自动删条目；重连后可刷新恢复 |
| 无读取权限 | “无法访问原文件” | 说明重新选择文件的方法，不引导申请全盘访问 |
| 原路径出现不同文件 | 不可仅凭同名就认定是原文件 | 能识别替换时要求用户重新选择；原应用正常保存导致的替换需专项验证 |

技术建议是“路径 + 轻量文件引用”，不是仅存一段路径文字。Apple 的 URL 书签机制可以用于重新解析资源位置，但具体恢复效果需验证；它不意味着把原文件复制进萌生。见 [Apple NSURL 文档](https://developer.apple.com/documentation/foundation/nsurl)。本版不新建 App Sandbox 方案，也不承诺书签可以绕过访问权限。

### 3.7 与现有能力的关系

- 剪贴板仍按现有范围记录文本、链接和图片，复制文件不会自动把它加入中转站。
- 文字拖入保存灵感、文件拖入保存引用，使用清晰区分的反馈文案。
- 文件拖入不依赖桌宠是否显示。建议设置增加独立的「文件拖入中转站」开关，默认开启；关闭现有「文字拖入收录」不应连带关闭文件功能。
- 全屏、屏幕几何不可用或现有刘海热区禁用时，不扩大透明热区接收文件。无刘海屏通过已打开的中转站页拖入。
- 本版全局搜索继续检索灵感、剪贴板和提示词，不默默扩大到文件正文。中转站文件名搜索作为后续需求，不在本版默认新增。
- 数据目录迁移只迁移引用记录，不搬动被引用的原文件；旧版本数据升级不得清空其他内容。

## 4. 顶部导航调整

### 4.1 默认结构

```text
灵感  剪贴板  提示词   [物理刘海留空]   灵感库  对话  中转站   [搜索图标] [设置图标]
```

- 搜索固定在设置左侧，只显示放大镜图标；设置继续为纯图标。
- 中转站是一级标签，使用文件夹图标；正常宽度优先显示「文件夹图标 + 中转站」，空间不足时可按现有导航逻辑降级为图标。
- 搜索功能仍在面板内呈现；从标签变成按钮不等于删除搜索页或改成独立窗口。
- 搜索激活时高亮搜索按钮，避免同时显示一个无关业务标签处于选中状态。
- 搜索、设置及图标化标签均须有悬停说明、辅助功能名称和明确焦点状态。
- 保留物理刘海占位，不将新按钮塞进黑色刘海区域。右侧空间不足时先按一致规则隐藏业务标签文字，不缩小按钮到难以点击，也不挤掉搜索或设置。

### 4.2 快捷键及旧设置兼容

| 项目 | 建议规则 |
| --- | --- |
| ⌘1～⌘6 | 对应六个业务标签的实际排序；默认 ⌘6 为中转站 |
| ⌘F | 继续进入全局搜索并聚焦输入框；搜索不再参加数字位置排序 |
| ⌘, | 继续打开设置 |
| 已自定义标签顺序 | 用中转站替换旧顺序中的搜索位置，其余相对顺序保留 |
| 默认入口 | 中转站可设为默认入口；旧默认入口是搜索时，仍能直接进入搜索页，不因入口形式改变而失效 |
| 设置中的排序列表 | 只列出六个业务标签；搜索、设置归为固定工具按钮，不参与拖动排序 |

数字快捷键变化在后续版本说明中明确提示。搜索页返回、详情返回搜索结果、带未保存编辑内容切换入口等场景，都继续遵循已有内容保护逻辑。

## 5. 验收标准

### 5.1 文件引用与拖拽

| 编号 | 场景 | 通过条件 |
| --- | --- | --- |
| F01 | 拖入一个大文件 | 成功保存引用；萌生数据目录没有该文件副本、文件正文或临时导出文件；数据增长与元信息相符 |
| F02 | 单文件拖出到网页上传区、聊天附件区 | 接收方获得真实附件，可打开且与原文件一致，不是路径文字；无原文件移动/删除 |
| F03 | 取消拖拽、目标拒收、上传失败 | 原文件与中转站记录均保留；无“已发送成功”误报 |
| F04 | 同一文件重复加入、不同目录同名文件 | 前者去重并前置，后者独立展示且可区分父目录 |
| F05 | 重启萌生/系统 | 引用记录仍在，可用文件仍能拖出，不要求重新拖入 |
| F06 | 原文件修改、改名、移动、删除、同路径替换 | 使用当前文件；可重新定位则恢复，无法确认则明确不可用，不无声引用错误文件 |
| F07 | 外接盘断开/重连、权限不足、云占位文件 | 反馈可理解，不卡住列表、不自动删引用、不隐式复制下载 |
| F08 | 移除单项、清空列表、撤销 | 只操作引用；原文件内容、位置和数量不变 |
| F09 | 多文件加入、批量拖出、其中含失效项 | 加入时给出新增/重复/失败数量；拖出不静默丢项，按规则指出失效项 |
| F10 | 文件夹、中文名、空格和特殊字符 | 引用路径正确；文件夹不被自动遍历或压缩；接收能力按目标应用记录 |
| F11 | 同一拖拽同时带文件和文字类型 | 文件只进入中转站，纯文字仍进入灵感库，不重复收录 |
| F12 | 关闭桌宠、关闭文字收录、无刘海屏 | 文件功能按独立开关工作；中转站页内拖入可用 |
| F13 | 拖出过程中移出面板、按 Esc 取消、目标弹出附件确认 | 拖拽不断裂，面板收起合理，目标应用焦点不被抢走 |

兼容性需在真实接收端验收：至少覆盖 Safari、Chrome 的实际文件上传组件，以及微信、飞书的桌面聊天附件区。记录系统/应用版本、目标页面、文件类型与结果；验证到“附件被接收并可打开”，不能仅检查拖拽事件已触发。文件夹和批量拖出单独记录，不以单文件通过推定全部通过。发送测试使用测试会话或草稿，不向真实联系人自动发消息。

### 5.2 导航与兼容

| 编号 | 场景 | 通过条件 |
| --- | --- | --- |
| N01 | 顶部导航 | 中转站为一级入口；搜索仅显示图标且位于设置左侧；保留物理刘海占位 |
| N02 | 偏好迁移 | 自定义顺序、默认入口和原搜索入口可用；数字快捷键与新导航一致 |
| N03 | 自适应 | 沿用 1.0.6 默认／展开布局与连贯动效；不同尺寸无遮挡，键盘及图标说明可用 |
| N04 | 数据回归 | 原有灵感、剪贴板、提示词和用户偏好不丢失；文字拖入不误识别为文件 |

## 6. 实施顺序

1. 验证原文件引用的拖入、持久化、重新定位和向真实接收应用拖出，确认不产生文件副本。
2. 完成中转站页面、异常状态、多选及撤销。
3. 完成顶部搜索按钮、中转站标签与导航偏好迁移。
4. 按文件验收表检查真实接收端，回归 1.0.6 布局和现有操作，再安排版本发布。
