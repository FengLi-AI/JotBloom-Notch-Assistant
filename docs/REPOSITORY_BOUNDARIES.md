# 仓库边界与协作

## 两个仓库，一套基础源码

| 内容 | 维护位置 | 对外提供 |
| --- | --- | --- |
| 灵感库、剪贴板、提示词、AI 对话、搜索、基础设置 | 本公开仓库 | MIT 源码，可独立构建 |
| 通用面板事件、存储接口与后续扩展接口 | 本公开仓库 | 随基础功能公开 |
| 桌宠、角色动作、刘海拖入灵感及动效、拓展设置 | 独立私有仓库 | 未来随官方客户端分发编译产物 |
| 授权校验、设备名额、支付回调及服务端代码 | 独立私有仓库 | 后续开发，不公开实现或密钥 |
| 官网、公共文档、反馈与发行记录 | 本公开仓库 | 共用一个官网与公共反馈入口 |

私有仓库通过固定提交的依赖引用本仓库，禁止复制一份基础源码后长期各自维护。仅克隆本仓库即可构建免费客户端；不能因为缺少商业模块而编译失败、启动报错或要求激活。

## 功能如何衔接

基础层负责面板、灵感存储等原有能力。后续按实际需要增加通用接口，例如面板展开/收起事件、保存灵感服务；接口仍公开且允许没有任何拓展实现。

私有拓展调用基础接口并响应事件，控制桌宠生命周期与付费交互。拖拽入口和表现放在拓展，灵感保存继续复用基础存储；未激活、授权失败或断网不得阻止原有手动记录。不要把基础数据格式与某个付费状态绑定。

官方完整客户端在私有构建环境中组合基础源码和商业模块。公开构建始终只包含基础功能；官方完整客户端的基础部分仍保留原开源许可和第三方声明。

## 一次跨模块迭代

1. 基础改动先在公开仓库提交、验证并合入。
2. 私有仓库更新固定依赖版本，再实现拓展并验证完整客户端。
3. 发布记录标注产品版本、基础提交和拓展提交，便于定位与回退。
4. 官网与公开 Release 可以提供官方编译安装包；不要上传私有源码包、内部设计素材或密钥。

GitHub 自动生成的 Source code 下载对应公开仓库内容，不等同于含商业拓展的完整源码。

## 当前准备状态

本次仅准备仓库边界、文档和检查入口，不改变 1.0.4 功能或发布新版本。付费功能、扩展接口、支付与授权尚未接入；后续实现时再确定具体接口，不预先给免费功能增加激活判断。

## 提交与推送检查

```sh
python3 scripts/check-repository-boundary.py
git config core.hooksPath scripts/git-hooks
```

检查会拦截已知商业目录、桌宠预览文件、凭据与用户数据文件；推送钩子额外检查将要推送的提交树，避免文件先提交后删除仍混入公开历史。CI 对公开分支重复检查。它是辅助措施，代码或素材改名后仍需人工审查其归属。
